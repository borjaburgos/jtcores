# Link2P review — 2026-09-15

## Scope

Reviewed the POC changes relative to their upstream merge base, not unrelated
newer upstream commits: Pocket transport/session/video/reset integration,
guarded JTBUBL restart logic, tests, ROM-backed simulation harness, build and
package identity, SD installation, and the accompanying documentation.
The pre-experiment source is JTCORES `bf03226e3` with Pocket
`cba779bec51cbd47477c1452277d6096d220251a`. Work remains in `borjaburgos/*`;
no upstream PR or release is implied.

JOTEGO's suggested direction is sound: recover short communication errors
before they become missing game inputs, and keep the protocol independent of
one game. It does not establish that the observed hardware resets were actual
cable removals. The protocol must report evidence rather than assume a cause.

## Findings and changes

1. **The old protocol already retries, but only the newest input.** Tested
   0.1, 1, and 5 ms gaps at the original sample-boundary phases pass on v1.
   A roughly 18.895 ms interruption covering an entire transmission window
   loses an input and resets. Version 2 repeats the previous capture as well,
   keeping it available until its N+2 application deadline. Changing controls,
   including Coin/Start, are scored on both peers; stale substitution is not
   allowed. This is bounded retransmission, not live-state recovery.
2. **CRC-8 is too weak for the observed corruption pattern.** Expanding the
   224-bit draft's 5 ms outage test to eight frame phases exposed an accepted
   damaged packet: the previous sample changed from `0xb70` to `0xfff` while
   the receiver still reported a valid checksum. The conflict safely reset
   the game. Version 2 now uses a 248-bit packet with CRC-32/MPEG-2. The
   packet-state checks remain necessary; a checksum cannot detect every
   possible error or prove hidden game-state equality.
3. **Video fingerprints need independent frame identity.** The old comparison
   used the input target while its CRC bus updated separately. The new packet
   labels the CRC's own completed frame and captures the bus after a documented
   settling delay. It only compares equal tags. This removes a structural
   false-comparison risk; we have not reproduced that risk as the cause of a
   physical reset. Genuine same-frame mismatches still fault.
4. **Invalid traffic must not suppress timeout.** Only a compatible RUN packet
   in the current session can satisfy the RUN timeout boundary. A unit test
   continuously asserts invalid receive slots and checks that timeout occurs.
5. **Recovery erased useful fault context.** The last fault, damaged-packet,
   recovered-input, and missed-deadline counters now survive session restart.
   The status grid and preserved nets expose them for hardware diagnosis.
6. **Separate session policy from cable handling.** `jtframe_link2p` has no
   Pocket pins or JTBUBL internals; the Pocket wrapper instantiates the serial
   adapter. Core identity is now declared by `JTFRAME_LINK2P_GAME_ID`, not
   hardcoded in Pocket top. The existing target location is retained during
   the POC. No JTBUBL gameplay RTL changed in this experiment.
7. **Do not relabel old bitstreams.** Packaging now requires the preserved
   builds' Pocket source commit to match the current pinned commit, in
   addition to the existing role/source/ROM/layout checks.

## Correction to the pause experiment

The September 1 `9f9d495c1` staggered pause run is **inconclusive**. In
`link2p_dual_game_test.sv`, instance B receives `SDRAM_DQ` from instance A's
modeled SDRAM, without an independent model responding to B's controller.
After the deliberate pause separates their accesses, B may receive data for
A's address. The reported repeated MCU resets therefore do not establish
that the game's pause mechanism fundamentally cannot preserve state.

The pause runner now fails early with this explanation. It needs two
independent memory models before another pause result is meaningful. Earlier
matched-execution video/audio runs remain observations of that harness, not
proof of independent memory or correctness under divergent accesses. No
freeze/resume implementation is being justified using those results.
The dashboard also labels these historical results inconclusive rather than
presenting their raw comparison failures as evidence against recovery.

## Generalization contract

Reusable now: compatibility/session logic, two-player digital input history,
deadlines, checksums, diagnostics, and the reset policy. Integration still
needs a stable frame marker, a verified CRC settling bound, final active-low
controls, and the existing reset request. Parameters expose role, game/build
identity, timeouts, and video comparison.

Not automatic: deterministic reset of every game's state, ROM/DIP agreement,
analog controls, more than two players, runtime menu/role selection, or
arbitrary oscillator drift. The guarded JTBUBL RAM scrub remains justified
by its prior warm-reset failure and cannot initialize another game's RAM.
Each new core must pass its own independent-memory and real-gameplay tests.
Moving the session into shared JTFRAME HDL can follow once this interface has
been validated on another core and discussed with JOTEGO.

## Validation and release gate

`make link2p-unit` exercises serial transport, startup, controls/reconnection,
identity faults, sequence/deadline boundaries, generic session guards, and
JTBUBL RAM clearing. The generic session test crosses 65,536-frame wrap with
changing inputs and verifies genuine video mismatch detection.

`make link2p-tolerance` uses the real serial RTL at 48 MHz and 250 kHz with
synthetic game markers. It flips each packet bit in both directions and tests
all-wire, individual-data-wire, and clock-only loss; 0.1/1/5 ms bursts; eight
frame phases; floating-high SCK; and sustained loss. Profiles cover roughly
59.19 Hz, 60 Hz, and 50 Hz with different peer phases. The approximately
18.895 ms history-recovery case applies to the nearly aligned profile only.
These are sampled fault scenarios, not an exhaustive electrical model or
ROM-backed gameplay evidence. Detailed completed results go in `RESULTS.md`.

Before calling this hardware-ready: all regressions and integration lint must
pass, both role variants must meet Quartus timing, and packages must identify
their exact source. Before calling the stability problem fixed: repeat the
handled-device diagnostic and family gameplay tests with both cables, record
persistent fault/counter evidence, and confirm clean reset after sustained
loss. No SD formatting or firmware change is required by this protocol update.
